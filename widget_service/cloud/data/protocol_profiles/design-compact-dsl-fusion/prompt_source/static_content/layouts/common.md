# 布局

## 文档式根布局

| 角色 | 适用条件 | 承载内容 | 使用边界 |
|---|---|---|---|
| header | 有必要共同标题 | SingleLineTitle | 可选，ID为header |
| body | 有正文 | 本尺寸静态正文组件 | 必填，ID为body |
| note | 有必要共同说明 | SecondaryBody | 可选，ID为note |

无动作使用本尺寸文档式布局；root为Layout，children按[header?,body,note?]排列。
没有共同标题/说明就省略，不创建空容器。

## 变体

| 名称 | 适用条件 | 对齐 / 间距 | 使用边界 |
|---|---|---|---|
| flow | 默认文档排版 | 区块纵向间距6 | 默认variant |
| compact | 紧凑文档排版 | 区块纵向间距4 | 正文仍须完整可见 |
| bottom-content | 根正文贴底 | 沿用标准区块间距 | 不能有note，也不能叠加ContentBlock.bottom-attributes |

有Action才开放本尺寸登记的兼容动作布局；不能给新内容组件加onClick。

## 容量核算

按实际参考内宽和所需行盒核算：先扣安全区、标题、note、侧栏、分栏内边距和间距，再算文字。
字号和行高由共享合同拥有，不任意缩字；每字段不超上限后还须检查整卡总高。
可见文字直接写入语义源，省略后的版本仍参与度量。
不要把单个组件最多3条误当整卡只能3条；可在Plan中选择合法的完整属性表，无法完整承载则如实失败。
