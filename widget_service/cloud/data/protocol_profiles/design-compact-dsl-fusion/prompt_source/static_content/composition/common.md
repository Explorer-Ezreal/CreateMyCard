# 组织与选型流程

## 形成可放下的展示版本

先把过长事实总结为能独立理解的短展示版本，再按名称、结论、键值、侧栏或细节拆分并归同一对象。
不要把名称、时间、数值、条件全部塞进一条text后期待程序自动拆句，也不要以长原句拆成多项must代替总结。
同对象多个短字段可分层承载，不把所有文字压成一段，不为占满卡片机械添加标题或来源。
长条件放全宽，不挤侧栏或对比窄栏；标签通常2–6字，正文优先短结论。

## 按信息结构选组件与布局

| 信息结构 | 适用条件 | 承载方式 | 使用边界 |
|---|---|---|---|
| 单对象结论 | 一个主体的结论与关联说明 | content / ContentBlock | 优先全宽 |
| 真正键值集合 | 短键值 | attributes / ContentBlock | 每行有清楚归属 |
| 多对象名称与说明 | 同构记录 | records / RecordList | 不把独立记录改成分类属性 |

按presentationStyle的结构意图和displayRole落实名称、主值、正文与辅助层级；
这些角色不授权新增事实或遗漏已接受内容。记录突出名称、说明弱化，短值独立对齐；
属性标签与值分列，长值保持本行归属。

对象超过3个且用户明确要求完整展示全部对象时，不能选择RecordList；改用实际容量成立的短键值表，
无合法结构时如实失败，不通过超限Plan将矛盾后移。

对象、共同上下文与动作确定后，选择当前尺寸合法父布局；动作使用兼容布局。
空间不足先去装饰、切换合法组件、把侧栏移本条全宽，最后整项省略无保护should，must完整保留。
先尝试12字号的清楚结构，再尝试11、10保留完整信息，之后才省略should；不要直接统一降到10。
